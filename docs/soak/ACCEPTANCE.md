# Soak 手工验收清单（#168 P2）

自动化覆盖不了的场景（桌面端壳层、物理硬件、OS 电源管理）。逐项手工执行，
结果记录在 Issue #168 或发布说明中。**任何一项失败按 #168 要求归类：
「代码缺陷」或「测试方法缺陷」，并修复。**

通用准备：release 构建（`cargo build --release`）+ 桌面端安装包；每项独立
环境（新数据目录），避免账本互相污染。

---

## 1. 桌面端 24 小时运行

| | |
|---|---|
| 步骤 | 启动 desktop，添加 5 个真实任务（混合 HTTP 大文件 + BT 种子），保持运行一夜 |
| 采样 | 每小时记录一次：任务管理器中 `smart-dl-daemon` 的内存 / 句柄数 / 线程数（截图或手记） |
| 通过标准 | ① 无崩溃、无 panic 弹窗 ② 内存增长 ≤ 20%（相对首小时基线）③ 句柄数无单调增长 ④ 全部任务达终态且文件 SHA256 正确（HTTP 任务可对照源站校验和） |
| 已知参考 | 自动化 soak-http（本目录）已覆盖服务端同口径断言；本项重点是**壳层共存**下的行为 |

## 2. 关窗后进程退出

| | |
|---|---|
| 步骤 | 任务下载中直接关闭桌面窗口（标题栏 ×） |
| 通过标准 | 5 秒内 `smart-dl-daemon` 进程消失（`Get-Process smart-dl-daemon` 为空 / `pgrep` 为空）；无孤儿进程 |
| 注意 | 若失败，先确认桌面壳是否启用了「最小化到托盘」语义——那是**预期行为**不是缺陷，改为托盘退出菜单验证 |

## 3. 强杀壳进程

| | |
|---|---|
| 步骤 | 任务下载中，任务管理器「结束任务」desktop 壳进程（不给清理机会，等价 kill -9） |
| 通过标准 | daemon 在 5 秒内自动退出（Job Object / 进程组联动）；无残留 `smart-dl-daemon` |
| 对照 | 服务端等价场景已自动化：`soak-failure-inject.sh kill9`（但方向相反——那边杀 daemon 留壳） |

## 4. 移动硬盘拔插

| | |
|---|---|
| 步骤 | dest 指向外置盘，下载中途物理拔出（不安全弹出） |
| 通过标准 | ① 不崩溃 ② 任务进入可诊断错误态（error 信息含 I/O 语义，非空白）③ 插回后 resume 能续传且终文件 SHA256 正确 |
| 对照 | 写失败路径已自动化近似：`soak-failure-inject.sh diskfull`（ulimit -f 模拟写失败 + 恢复续传断言） |

## 5. 系统休眠唤醒

| | |
|---|---|
| 步骤 | 下载中休眠 ≥ 1 小时，唤醒 |
| 通过标准 | 唤醒后任务自动恢复下载（连接重建）；若源端已失效，进入重试/Failed 而非挂死；终文件 SHA256 正确 |
| 对照 | 连接冻结/恢复已自动化：`soak-failure-inject.sh netdown`（SIGSTOP 模拟连接僵住，含 30s 短断与 75s 超读超时两档） |

## 6. 大文件（>50GB）

| | |
|---|---|
| 步骤 | 单任务 >50GB（如蓝光镜像/大模型权重），观察全程 |
| 通过标准 | ① 内存平稳（账本内存占用与段数线性、与文件大小无关——分段常量 16MB）② 中途 kill -9 后恢复不重下 ③ 终文件 SHA256 正确 |
| 磁盘 | 需 ≥ 110GB 可用空间（文件 + 预分配 .part） |

## 7. 多任务并发（50 个）

| | |
|---|---|
| 步骤 | 同时添加 50 个任务（混合大小/引擎），观察队列执行与 UI |
| 通过标准 | ① 队列按 `[queue]` 配额执行（不超额并发）② UI 不卡顿（列表滚动、任务详情切换 < 200ms）③ 无任务被饿死（10 分钟内至少开始执行）④ 全部完成后 `/tasks` 响应 < 1s |
